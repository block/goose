# WooYun 历史案例工作流

## 使用场景

- 需要对注册、登录、找回密码、订单、支付、退款、权限管理等业务流程做逻辑安全排查时
- 需要从认证、授权、金融、信息泄露、流程设计、配置缺陷等领域快速组织测试假设时
- 需要把安全测试结果整理成“业务影响 + 证据 + 修复建议”的报告，而不是只给零散 payload 时

## 输入要求

- 至少提供目标系统中的一类上下文：业务流程、接口清单、角色模型、请求样本、测试范围或已有异常现象
- 如果希望使用 WooYun 上游历史参考资料，先在本机执行 `node scripts/install-wooyun-legacy-skill.mjs <path>` 安装外部参考包
- 如果外部参考包未安装，必须明确以“本地包装模式”执行，不得虚构历史案例数量、原始案例标题或上游统计结论

## 执行步骤

1. 先画清业务流程：核心角色、状态流转、资金流、敏感数据流、信任边界。
2. 把待测点归入一个或多个领域：认证、授权、金融、信息、逻辑流、配置。
3. 如果 `.agents/skills/wooyun-legacy/external/upstream/references/` 下存在对应领域文件，先读取匹配参考文件，再形成测试假设；如果不存在，继续按本地包装模式执行。
4. 为每个领域输出最小假设集：哪条流程、哪种绕过方式、为什么值得优先验证、需要观测哪些服务端证据。
5. 只做最小必要验证：单参数改动、跨账号对比、状态跳转验证、订单金额与权限边界验证；不把未授权攻击操作写成建议步骤。
6. 归纳业务影响、利用条件、修复建议，并标明哪些是直接证据，哪些只是历史模式类比。

## 风险与边界

- 本 skill 只用于授权测试、复盘、加固和防守分析，不用于未授权攻击
- WooYun 历史数据覆盖的是公开历史案例，不代表当前技术栈的实时风险分布
- 如果未安装外部参考包，不得捏造“上游案例/统计/原始标题”来增强结论
- 历史案例只能作为类比证据，不能替代当前系统的真实验证结果

## 验证步骤

- 复查是否显式写明本次执行是“本地包装模式”还是“上游参考增强模式”
- 复查每个结论是否能对应到当前目标的真实证据，而不是只对应历史类比
- 复查是否至少输出了业务流程、领域分类、测试假设、业务影响和修复建议
- 复查报告中是否避免了未授权操作指引和无法验证的历史数据断言
