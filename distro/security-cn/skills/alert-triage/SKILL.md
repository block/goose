# 告警分析

## 使用场景

- 用户给出告警标题、规则命中结果、日志片段或事件时间线时
- 需要先判断告警更像真实攻击还是噪音时
- 需要把调查结果整理成适合值班、安全运营或工单流转的结论时

## 输入要求

- 至少提供告警来源、时间窗、命中规则或原始事件中的一项
- 如果存在多条日志或多类证据，优先按主机、账号、进程、网络、时间线分类
- 如果缺少原始日志、资产归属或检测规则描述，先把缺口列出来

## 执行步骤

1. 明确告警上下文：来源系统、规则名称、命中条件、时间窗、事件对象。
2. 提取关键证据：主机、账号、IP、进程、文件、URL、命令行、时间线。
3. 判断规则命中是否合理，区分规则误报、正常运维行为和攻击迹象。
4. 识别受影响资产和潜在业务影响，说明当前证据是否足以升级处置。
5. 给出真实性判断、风险等级和建议动作，并单列待补充数据。

## 输出模板

```markdown
### 告警真实性判断
- 结论：
- 依据：

### 触发原因
- 直接触发点：
- 深层原因：

### 受影响资产
- 资产：
- 业务影响：

### 风险等级
- 等级：
- 判断依据：

### 建议处置动作
- 立即动作：
- 继续调查：

### 待补充数据
- 缺口 1：
- 缺口 2：
```

## 风险与边界

- 不要把单条命中规则直接等同于入侵事实
- 不要在缺少时间线或原始日志时给出过强归因
- 如果是正常运维或自动化任务的高概率事件，要明确写出佐证
- 建议动作必须和当前证据强度匹配，避免过度处置

## 验证步骤

- 复查真实性判断是否有直接证据支持
- 复查触发原因是否和规则命中点一致
- 复查受影响资产和风险等级是否匹配
- 复查建议动作能否被值班或工单系统直接消费
