# 资产风险汇总

## 使用场景

- 用户给出资产清单、暴露面、漏洞列表、告警统计或混合风险线索时
- 需要先形成“当前哪些资产更值得优先看”的摘要时
- 需要产出适合周报、排班交接或管理汇报的风险概览时

## 输入要求

- 尽量提供资产标识、业务归属、暴露面信息、风险线索来源和时间范围
- 如果输入来自多个系统，先标明每个系统的覆盖边界和可信度
- 如果资产状态未知、数据时间过旧或口径不同，必须先写出口径风险

## 执行步骤

1. 归并输入：按资产、业务、风险类型、时间窗组织。
2. 标出高优先级资产：公网暴露、关键业务、存在高危漏洞、重复告警或高价值账号相关。
3. 说明每类风险的数量、代表性案例和可能影响。
4. 区分“已证实高风险”“需要继续确认”“低确定性噪音”三类。
5. 给出优先级明确的下一步动作和补充数据清单。

## 输出模板

```markdown
### 风险概览
- 资产总览：
- 高风险资产数量：
- 主要风险类型：

### 重点资产
- 资产 1：
- 风险原因：

### 代表性证据
- 证据 1：
- 证据 2：

### 口径与不确定项
- 数据口径：
- 不确定项：

### 建议下一步
- 立即优先级：
- 本周跟进项：
```

## 风险与边界

- 不要把“数据缺失”误写成“风险不存在”
- 不要仅按单一严重度排序，必须同时考虑资产重要性和暴露面
- 不同数据源口径不一致时，必须先说明再汇总
- 汇总输出必须保留样本证据，避免只给统计没有支撑

## 验证步骤

- 复查高风险排序是否同时考虑资产重要性与攻击面
- 复查概览统计是否和输入口径一致
- 复查代表性证据能否支持结论
- 复查下一步动作是否能直接形成跟进清单
