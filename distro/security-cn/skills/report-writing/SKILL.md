# 安全报告生成

## 使用场景

- 用户已经完成部分调查，需要整理成报告、汇报稿、交接摘要或工单内容时
- 需要把多个调查片段收敛成一致口径时
- 需要显式区分已证实事实、判断结论和待确认项时

## 输入要求

- 提供调查背景、时间范围、调查结论、关键证据和建议动作
- 如果输入来自多个子任务，先按主题归并，避免报告重复
- 如果已有固定汇报格式或目标读者，先说明

## 执行步骤

1. 明确目标读者：值班分析员、漏洞处置人、管理者、审计或客户。
2. 先收敛核心结论，再补关键证据和不确定项。
3. 去掉过程噪音，保留决策所需事实、判断依据和行动建议。
4. 用一致术语组织风险等级、影响面、证据来源和下一步动作。
5. 在最终稿中单列“待确认项”，避免把未完成调查伪装成完整结案。

## 输出模板

```markdown
### 背景
- 任务背景：
- 时间范围：

### 核心结论
- 结论 1：
- 结论 2：

### 关键证据
- 证据 1：
- 证据 2：

### 影响与风险
- 影响范围：
- 风险等级：

### 建议动作
- 立即动作：
- 后续动作：

### 待确认项
- 待确认项 1：
- 待确认项 2：
```

## 风险与边界

- 不要把调查过程中的猜测写成正式结论
- 不要省略影响范围和证据来源
- 不要为了简洁删掉关键不确定项
- 如果读者需要管理视角摘要，仍然要保留可追溯证据

## 验证步骤

- 复查核心结论是否一眼可读
- 复查每个结论是否能回溯到证据
- 复查建议动作是否明确负责人和优先级
- 复查待确认项是否被单独列出，没有混入结论
