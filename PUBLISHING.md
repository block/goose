# Publishing this fork

This branch is based on the official Goose `v1.45.0` tag and contains two
user-facing additions: resilient ChatGPT Codex retries and an optional Windows
GGUF model picker for llama.cpp.

## Commit to the repository

- `crates/goose/src/providers/chatgpt_codex.rs`
- `tools/windows-gguf/`
- `PATCH_RELEASE.md`
- `PUBLISHING.md`
- The upstream source, license, notices, and lockfiles already tracked by Git

Keep the Apache-2.0 `LICENSE` and upstream attribution intact. Describe the
project as an unofficial fork, not an official Goose release.

## Do not commit

- GGUF model files or any other model weights
- `%APPDATA%\Block\goose\config\` or its provider configuration files
- `models\local-models.json` generated by the helper
- ChatGPT/Codex tokens, cookies, API keys, `.env` files, or keyring exports
- Goose logs, session history, screenshots containing private data, or crash dumps
- `target\`, `node_modules\`, build caches, temporary files, or local backups
- The original installed `resources\bin\goose.exe`
- Personal absolute paths or machine-specific configuration

## Release assets

A compiled patched `goose.exe` may be attached to a GitHub Release for user
convenience. Do not commit it to normal source history. Publish its SHA-256,
the exact source commit, build command, enabled features, and the upstream tag.
Clearly note that the portable build excludes any feature omitted from the
build command.

The GGUF helper scripts may be shipped either in the source archive or as a
small separate ZIP. They do not include or upload model weights.

## Pre-publish checks

```powershell
git status --short
git diff --check
rg -n -S "access_token|refresh_token|CHATGPT_CODEX_TOKEN|Authorization: Bearer" .
cargo test -p goose-provider-types retry::tests::
cargo check -p goose
```

Review every changed file before committing. Then create a release from a
named tag rather than publishing an unidentifiable working-tree binary.
